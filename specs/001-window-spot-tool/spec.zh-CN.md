**输入**：用户描述——Windows 窗口工具：拖拽绑定选中窗口并显示 HWND/标题/客户区大小；点击客户区显示相对坐标与颜色（可复制）；框选客户区区域并给出可复制相对坐标；F12 客户区截图且可配置保存路径/格式/质量；以 C# WPF 单文件 exe 交付。

## 澄清记录

### Session 2026-09-30

- Q: 探测模式改为 Tab 后，空闲 / 拾取 / 框选及结果区应如何组织？ → A: 三个 Tab（无 / 拾取 / 框选）；每个 Tab 仅显示该模式相关结果与提示。
- Q: 点击「复制」后，按钮视觉反馈与顶部「已复制」提示应如何表现？ → A: 按钮短暂成功态（约 1.5 秒）+ 顶部「已复制」提示（约 2 秒），均自动恢复/消失。
- Q: 应用图标应采用哪种视觉主题以体现 WinSpot？ → A: 抽象「W」字母标（弱功能隐喻）。
- Q: 移除界面最上方「WinSpot」标题与介绍时，范围包含哪些部分？ → A: 仅移除内容区顶部标题+介绍横幅；系统窗口标题栏仍为 `WinSpot`。
- Q: 选中拾取/框选 Tab 时，指针交互与模式退出应如何工作？ → A: 指针在 WinSpot 窗口内保持正常光标与点击；仅离开 WinSpot 后才进行拾取/框选。完成一次拾取/框选后 Tab MUST NOT 自动切回「无」；按 Esc 结束探测并选中「无」（主动选择「无」Tab 同样退出）。
- Q: 除 Esc 外，用户能否通过选择「无」Tab 退出探测模式？ → A: 能——Esc 或选择「无」Tab 均可结束探测并回到「无」。
- Q: 选中「拾取」或「框选」后，鼠标在 WinSpot 之外应显示什么光标？ → A: WinSpot 外使用模式光标（拾取/框选为十字或准星）；回到 WinSpot 内恢复正常光标。
- Q: 将截图快捷键改为 F12 时，本版是否仍只固定默认键、不提供界面改键？ → A: 固定默认 F12；改键仍可延后（冲突时仍须非致命提示）。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 绑定窗口并查看信息（优先级：P1）

用户打开 WinSpot，将绑定准星拖到可见桌面窗口后松开，工具立即显示该窗口的句柄、标题、客户区大小及相关身份字段。字段可复制，便于记入其它工具或笔记。主内容区不显示大型「WinSpot」标题/介绍横幅；系统窗口标题仍为 `WinSpot`。

**优先级理由**：绑定与身份信息是后续测量与截图的基础。

**独立测试**：绑定记事本（或资源管理器），核对 HWND/标题/客户区大小，并成功复制各字段。

**验收场景**：

1. **给定** WinSpot 已启动且未绑定窗口，**当**用户将绑定控件拖到可见窗口并松开，**则**该窗口成为绑定目标，工具显示其句柄、标题与客户区大小。
2. **给定**已绑定窗口，**当**用户复制句柄或标题，**则**剪贴板为稳定格式文本（句柄仅为十进制数字，例如 `265098`）；复制控件短暂显示成功态约 1.5 秒；窗口顶部弹出「已复制」提示约 2 秒后自动消失。
3. **给定**已绑定窗口，**当**用户清除或重新绑定，**则**绑定被清除或替换，且工具不崩溃。

---

### 用户故事 2 - 客户区点击拾取（坐标 + 颜色）（优先级：P2）

绑定窗口后，用户选择「拾取」Tab。该 Tab 保持选中期间，WinSpot 窗口内仍为正常光标与完整 UI 点击；仅当指针在 WinSpot 之外（绑定客户区上）才进行拾取采样。成功拾取后仍停留在「拾取」Tab，便于连续拾取。按 Esc（或选择「无」Tab）结束拾取并回到「无」。

**优先级理由**：绑定之后，坐标/取色是日常核心工作流。

**独立测试**：绑定已知窗口，拾取角点与中点，与可信参考比对相对坐标与颜色（在约定容差内）；确认拾取模式下仍可点击 WinSpot UI；确认采样后 Tab 仍为「拾取」直至 Esc。

**验收场景**：

1. **给定**已绑定窗口且已选中「拾取」Tab，**当**用户将指针移到 WinSpot 窗口上，**则**光标与点击表现为正常 WinSpot UI（不进行拾取采样）。指针在 WinSpot 外时，光标为拾取/十字类光标。
2. **给定**已绑定窗口且已选中「拾取」Tab，**当**用户在 WinSpot 之外点击绑定客户区内，**则** WinSpot 在拾取 Tab 内显示相对客户区原点的 `(x, y)` 及该像素颜色，且仍保持「拾取」Tab 选中。
3. **给定**已显示拾取结果，**当**用户复制坐标或颜色，**则**剪贴板格式与界面一致（例如 `x,y` 与 `#RRGGBB`），并具备与其它复制操作相同的按钮成功态与顶部「已复制」提示。
4. **给定**已选中「拾取」Tab，**当**用户在绑定客户区外（且在 WinSpot 外）点击，**则** WinSpot 忽略该次点击或给出非破坏性提示，且不以错误数据覆盖上次有效拾取。
5. **给定**拾取完成后仍选中「拾取」Tab，**当**用户按 Esc **或**选择「无」Tab，**则**探测模式结束并选中「无」Tab。

---

### 用户故事 3 - 客户区框选（优先级：P3）

绑定窗口后，用户选择「框选」Tab。指针在 WinSpot 上时 UI 仍正常可点；仅在 WinSpot 外对绑定客户区拖拽才框选。成功框选后仍停留在「框选」Tab。按 Esc（或选择「无」Tab）结束框选并回到「无」。

**优先级理由**：区域测量建立在绑定之上；对裁剪/自动化规划有用，但次于单点拾取。

**独立测试**：在绑定客户区内拖出已知大小区域；确认拖拽中橡皮筋可见；核对报告的 `x1,y1,x2,y2`；确认框选后 Tab 仍为「框选」直至 Esc。

**验收场景**：

1. **给定**已选中「框选」Tab 且已绑定窗口，**当**用户在 WinSpot 窗口内操作控件，**则**点击正常生效且不启动框选；WinSpot 上为正常光标。WinSpot 外为十字类框选光标。
2. **给定**已选中「框选」Tab 且已绑定窗口，**当**用户在 WinSpot 外于绑定客户区内拖拽，**则**拖拽中可见选区轮廓，松开后在框选 Tab 内显示 `x1,y1,x2,y2`（左上/右下，相对客户区），且仍保持「框选」Tab 选中。
3. **给定**框选结果已显示，**当**用户复制区域描述，**则**剪贴板内容恰好为该 `x1,y1,x2,y2` 文本，并具备与其它复制操作相同的按钮成功态与顶部「已复制」提示。
4. **给定**拖拽超出客户区边界，**当**用户松开，**则**报告区域被裁剪到客户区内。
5. **给定**框选完成后仍选中「框选」Tab，**当**用户按 Esc **或**选择「无」Tab，**则**探测模式结束并选中「无」Tab。

---

### 用户故事 4 - 热键客户区截图与导出设置（优先级：P4）

绑定窗口后，用户按 F12 仅截取客户区，并按已配置的目录、文件名模板、格式与质量保存。设置跨会话持久化。本版不提供界面改键。

**优先级理由**：截图价值高但依赖可靠绑定；设置决定日常可用性。

**独立测试**：绑定窗口，设置保存目录/格式/质量，按 F12，打开文件确认仅为客户区内容且尺寸/格式符合预期。

**验收场景**：

1. **给定**绑定窗口可见且保存设置有效，**当**用户按 F12，**则**客户区图像保存到配置位置与格式，且内容与屏幕上合成可见画面一致（非空白/全灰）。
2. **给定**所选格式为 JPEG（默认），**当**用户更改质量后截图，**则**保存文件反映新质量。
3. **给定**绑定窗口已最小化、关闭或无法截取，**当**用户按 F12，**则** WinSpot 给出明确失败提示，且不以损坏/空文件当作成功。
4. **给定**用户更改保存目录/格式/质量，**当**应用重启，**则**仍使用这些设置。

---

### 用户故事 5 - 单文件桌面交付（优先级：P5）

用户下载或构建单个可执行文件，在未单独安装运行时的干净 Windows 10/11 x64 机器上运行 WinSpot。

**优先级理由**：分发交付要求；不阻塞本地构建演示，但发布必须满足。

**独立测试**：发布自包含单文件构建；在未预装 .NET 的环境启动并确认应用可运行。

**验收场景**：

1. **给定**已发布自包含单文件构建，**当**用户在 Windows 10/11 x64 上双击 exe，**则** WinSpot 启动且无需单独安装运行时。

### 边界情况

- 目标窗口关闭或绑定后句柄失效。
- 绑定后窗口移动、缩放或标题变化。
- 目标完整性级别高于 WinSpot（可能无法访问/截取）。
- 高 DPI 与多显示器影响屏幕↔客户区换算。
- 全局热键 F12 已被其它程序占用。
- 最小化、被遮罩或完全遮挡的窗口。
- UWP / 独占全屏 / 硬件保护内容可能无法得到准确像素（尽力而为并明确失败）。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统 MUST 允许用户通过拖放（或等价的从工具拖出）绑定可见桌面窗口。
- **FR-002**：系统 MUST 至少显示绑定窗口的句柄、标题、客户区宽高；字段 MUST 可复制。句柄 MUST 仅以十进制数字显示与复制（无 `0x` 十六进制前缀）。
- **FR-003**：系统 MUST 支持清除与重新绑定目标窗口。
- **FR-004**：系统 MUST 提供拾取模式：在绑定客户区内点击时，报告相对客户区左上角的坐标。
- **FR-005**：系统 MUST 以可复制的 RGB 和/或 HEX 形式报告拾取像素颜色。
- **FR-006**：系统 MUST 提供框选模式：在绑定客户区内选择矩形，拖拽时显示可见橡皮筋，并以可复制的 `x1,y1,x2,y2`（左上角与右下角，相对客户区）报告区域。
- **FR-007**：系统 MUST 将框选结果裁剪到客户区范围内。
- **FR-008**：系统 MUST 注册固定截图热键 F12，仅截取绑定窗口客户区。本版不提供界面改键。
- **FR-009**：系统 MUST 允许配置截图保存目录、图像格式（至少 PNG 与 JPEG）、JPEG 质量与文件名模板；设置 MUST 本地持久化。默认 MUST 为：JPEG 格式；文件名模板仅时间（例如 `{yyyyMMdd_HHmmss}`），不含窗口标题。
- **FR-010**：当绑定、拾取、框选或截图无法准确完成时，系统 MUST 给出明确错误提示。
- **FR-011**：系统 MUST 以所支持架构的自包含单文件 Windows 可执行文件交付。
- **FR-012**：客户区截图 MUST 使用 DXGI Desktop Duplication（与 Python dxcam 相同思路）捕获合成桌面像素；MUST NOT 以 GDI `BitBlt`/`GetDC` 作为截图后端。
- **FR-013**：系统 MUST 以互斥 Tab（而非单选按钮）呈现探测模式（无 / 拾取 / 框选）。每个 Tab MUST 仅显示该模式的结果与提示；选中某 Tab 即激活对应模式。
- **FR-014**：每次成功复制到剪贴板时，系统 MUST：（a）将被点击的复制控件短暂切换为可感知的成功态约 1.5 秒后恢复；（b）在窗口顶部显示文案为「已复制」的提示约 2 秒后自动消失。
- **FR-015**：发布的可执行文件与主窗口 MUST 使用专用应用图标：抽象「W」字母标（非准星/滴管/框选隐喻）。图标 MUST 至少出现在 `.exe` 文件与窗口/任务栏外观上。
- **FR-016**：主窗口内容区 MUST NOT 显示带有应用名「WinSpot」与功能介绍文案的顶部宣传/标题横幅。系统窗口标题栏 MUST 仍显示 `WinSpot`。
- **FR-017**：当选中「拾取」或「框选」时：（a）指针在 WinSpot 主窗口上 MUST 保持正常光标，且 MUST 允许正常操作 WinSpot UI（绑定、复制、设置、切换 Tab 等）；（b）拾取/框选采样 MUST 仅发生于指针在 WinSpot 窗口之外的操作；（c）在 WinSpot 外，光标 MUST 为当前 Tab 对应的十字/准星样式；（d）成功完成一次拾取或框选后 MUST NOT 自动将 Tab 切回「无」——当前「拾取」/「框选」Tab MUST 保持选中以便连续操作；（e）按 Esc MUST 结束当前探测模式并选中「无」Tab；主动选择「无」Tab MUST 同样结束探测模式。

### 关键实体

- **BoundWindow**：当前选中目标；身份（句柄、标题、类名/进程等可得信息）与客户区几何。
- **ClientPointSample**：来自绑定客户区的相对 `(x,y)` 与颜色采样。
- **ClientRegion**：绑定客户区内的相对矩形（原点 + 尺寸）。
- **CaptureSettings**：保存目录、格式、质量、文件名模板（本版截图热键固定为 F12，不纳入持久化设置）。
- **CaptureResult**：客户区截图尝试的成功路径或失败原因。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：新用户可在首次启动 30 秒内完成绑定并读到句柄/标题/客户区大小。
- **SC-002**：对标准 Win32 窗口（如记事本），相对拾取坐标与可信参考零像素误差；在正常桌面合成下采样颜色每通道容差 ±1。
- **SC-003**：对屏上已知矩形，框选报告在裁剪后与期望相对边界一致。
- **SC-004**：对可见且可截取窗口，F12 产出图像像素尺寸等于绑定客户区尺寸，在典型开发机上于 2 秒内完成。
- **SC-005**：更改保存设置并重启后，下次截图无需重新配置即使用已存设置。
- **SC-006**：发布的单文件构建可在干净 Windows 10/11 x64 环境启动，无需单独运行时安装程序。
- **SC-007**：成功复制后，用户能在约定时长内同时感知到按钮成功反馈与顶部「已复制」提示，且不阻塞后续操作。
- **SC-008**：发布构建中，可执行文件图标与运行中窗口/任务栏图标均显示 WinSpot「W」字母标（非默认空白/通用图标）。
- **SC-009**：启动后一眼可见：主内容区无顶部「WinSpot」标题/介绍横幅，而系统窗口标题仍为 `WinSpot`。
- **SC-010**：选中「拾取」或「框选」时，指针下的 WinSpot UI 仍可操作且为正常光标；WinSpot 外显示模式十字/准星光标；成功采样后同一 Tab 保持选中，直至按 Esc 或选择「无」。

## 假设

- 主要用户为 Windows 10/11 x64 上的开发/测试/自动化作者。
- 首版同时仅绑定一个窗口（无多绑定）。
- 拾取与框选为互斥模式，通过 Tab（无 / 拾取 / 框选）切换；每个 Tab 仅显示该模式相关结果与提示。
- 选中「拾取」/「框选」时，指针在 WinSpot 上仍可完整操作工具本身且为正常光标；WinSpot 外使用模式十字/准星光标，探测输入仅作用于 WinSpot 之外。完成一次采样不回到「无」；按 Esc 或选择「无」才退出。
- 本版截图热键固定为 F12；界面改键仍可延后。注册冲突 MUST 给出明确的非致命提示。
- 默认图像格式为 JPEG；默认文件名模板为 `{yyyyMMdd_HHmmss}`（无 `{title}`）。
- 截图后端为 DXGI Desktop Duplication（dxcam 等价）；客户区通过对客户区屏幕矩形对应的合成桌面区域裁剪得到。
- OCR、进程注入、脚本化点击，以及独占全屏/受保护内容的完备捕获保证，不在本功能范围内。
- 对受保护/全屏内容允许尽力而为，但失败须对用户可见。
- 除句柄/标题/客户区大小外，「相关信息」在可无提权获得时，可包括类名、进程名/PID、客户区屏幕位置。
- 框选 `x2,y2` 为裁剪后的右下角，使用 `x1+width` / `y1+height`（与归一化拖拽终点一致）。
